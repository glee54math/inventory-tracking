# ShapesAndEqualSharesLab

**Proposed slot:** MG5 — provisional, confirm at build time per project convention.
**Grade:** 2
**Standards covered:** 2.G.1 (recognize and draw shapes with specified attributes — number of angles, number of equal faces — and identify triangles, quadrilaterals, pentagons, hexagons, and cubes); 2.G.2 (partition a rectangle into rows and columns of same-size squares, count the squares); 2.G.3 (partition circles and rectangles into two, three, or four equal shares, describe using halves/thirds/fourths/half-of/third-of, recognize that equal shares of identical wholes need not have the same shape)
**Relationship to existing labs:** No overlap with any live MG6 component — none of `TwoDigitVisualAddition`, `VerticalAdditionSubtraction`, or `BarModelPractice` touch geometry. Unit 2 (partitioning a rectangle into rows/columns of squares) deliberately echoes the array structure from `EvenOddAndArraysLab` (2.OA.4) as a natural cross-domain link — same visual grid idea, different purpose (here: counting via partition/structure rather than addition fluency) — so the two labs reinforce rather than duplicate each other. Unit 3 (equal shares) is the direct conceptual predecessor to MG9's `IntroToFractionsLab`; this lab stops at halves/thirds/fourths with concrete shape-partitioning vocabulary and does not introduce fraction notation (1/2, 1/3, etc.) or numeric fraction operations, which remain MG9's job.
**Audience framing:** Built for a student seeing this content for the first time, regardless of the standard's posted grade level. Favor shapes shown in irregular/rotated orientations as often as "textbook-perfect" ones, since the standard's own emphasis is that attribute COUNT defines a shape category, not a particular look — and for equal-share partitioning, always show at least one example where pieces are visually different in outline shape but equal in area, since that distinction is the unit's whole point.

## Units

### Unit 1: Classifying Shapes by Attributes
- **Goal:** Name a shape by counting its angles/sides, and draw a shape when given the attributes it should have.
- **Standard:** 2.G.1
- **Buckets:** identify a named 2D shape (triangle, quadrilateral, pentagon, hexagon) regardless of orientation or irregularity (e.g. a rotated or irregular hexagon is still a hexagon); identify a 3D shape (cube) by its equal-face attribute; draw/construct a shape given a specified angle or side count (e.g. "draw a shape with 4 angles"); classify a shape that must satisfy more than one attribute constraint at once (specified angle count AND equal side lengths); a trap case where an irregular, non-symmetric shape still technically qualifies for its category purely by attribute count, even though it doesn't "look like" the category's typical example
- **Requires intro (CFU gate):** Yes — target misconception is assuming shape categories require regularity/symmetry (that all pentagons or hexagons "look like" the standard textbook version), when the real defining criterion is strictly the attribute count (number of angles/sides, or equal faces for the cube); also risk of conflating 2D attribute-counting with the cube's 3D face-counting.
- **Memorization fact (periodic re-check candidate):** No — classification is reasoned from counting a given shape's attributes each time, not recalled; shape-name vocabulary itself is foundational but is treated as a classification skill here rather than an arithmetic-style memorized fact.

### Unit 2: Partitioning Rectangles into Rows and Columns
- **Goal:** Split a rectangle into equal-size square rows and columns, then count the total squares.
- **Standard:** 2.G.2
- **Buckets:** partition a given rectangle into a specified number of equal rows and columns (e.g. 3 rows by 4 columns), then count the total squares; given an already-partitioned rectangle, find the total by adding across rows (repeated addition, consistent with 2.OA.4's addition-based framing rather than a multiplication formula); a case where a naive/uneven partition attempt would produce squares that aren't actually the same size, requiring the student to recognize and reject it; reverse direction — given a total square count and one known dimension, determine the missing row or column count
- **Requires intro (CFU gate):** Yes — misconception risk of partitioning unevenly (squares that only look equal-sized) while still "appearing" partitioned, and of miscounting the total by only counting a border/edge of squares rather than the full grid.
- **Memorization fact (periodic re-check candidate):** No — each total is counted fresh from the specific rectangle's rows and columns.

### Unit 3: Equal Shares of Circles and Rectangles
- **Goal:** Split a circle or rectangle into 2, 3, or 4 equal-size pieces, and name them correctly as halves, thirds, or fourths.
- **Standard:** 2.G.3
- **Buckets:** partition into halves, using correct vocabulary ("halves," "half of"); partition into thirds, using correct vocabulary ("thirds," "a third of") — new beyond Grade 1, which only covered halves/fourths; partition into fourths, using correct vocabulary ("fourths," "quarters," "a fourth of"); recognize that two different, equally valid ways of cutting the SAME whole into halves (or thirds, or fourths) can look like different shapes but are still equal shares (explicit standard language); a trap case where a shape is cut into the right NUMBER of pieces but the pieces are NOT actually equal in size/area, so it does not count as true halves/thirds/fourths despite the piece count matching; a generalization comparison — a half of a whole is bigger than a third of the SAME whole (more shares = smaller pieces)
- **Requires intro (CFU gate):** Yes — the named misconception is assuming "cut into N pieces" automatically means "N equal shares," regardless of whether the pieces are actually equal in area; the identical-whole/different-shape idea (two valid ways to halve the same rectangle) is also genuinely counterintuitive on first exposure and needs explicit demonstration, not just one example.
- **Memorization fact (periodic re-check candidate):** No — this is a reasoned, re-derivable concept (check equal area each time) that deliberately builds toward fraction understanding rather than a recalled fact.

## Open questions / flags for the builder
- Unit 1 bundles both "recognize" and "draw" directions of 2.G.1 into a single unit (matching the standard's own single code) rather than splitting them into two units — flagging this choice since other labs in this batch split a single code across multiple units when its sub-parts were distinct (e.g. 2.OA.3's two sub-parts in `EvenOddAndArraysLab`); if the builder finds the recognize/draw split warrants separate Explore/Practice treatment once building it out, that's a reasonable adjustment within this plan's intent.
- Unit 2's rows-and-columns partition diagram and `EvenOddAndArraysLab` Unit 3/4's rectangular-array diagram are visually very similar (an equal-size grid); if `EvenOddAndArraysLab` is built first, check whether its array diagram component can be reused here rather than built twice (the "promote on the second real consumer" convention from the math-lab-builder agent brief would apply).
