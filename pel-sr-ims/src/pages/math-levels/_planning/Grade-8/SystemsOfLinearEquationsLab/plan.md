# SystemsOfLinearEquationsLab

**Proposed slot:** MM3 — provisional, confirm at build time per project convention. See the MM3-contention flag in Open questions (shared across all four grade-8 labs in this batch, and with grade 7's own MM3 proposal).
**Grade:** 8
**Standards covered:** 8.EE.8a (understand that solutions to a system of two linear equations in two variables correspond to points of intersection of their graphs, because points of intersection satisfy both equations simultaneously), 8.EE.8b (solve systems of two linear equations in two variables algebraically, and estimate solutions by graphing the equations — solve simple cases by inspection), 8.EE.8c (solve real-world and mathematical problems leading to two linear equations in two variables).
**Relationship to existing labs:** This is a direct SEQUEL to `LinearEquationsAndProportionalRelationshipsLab` (this grade's own other new lab, planned in this same batch). Sequence that lab first — this lab assumes a student already solves single linear equations fluently (including the distributive property and collecting like terms), already classifies an equation's solution count by simplifying to x=a/a=a/a=b form, and already graphs a line from an equation and reads its slope. This lab does not re-teach any of that; it extends single-equation solving and graphing to pairs of equations considered TOGETHER, and the one/infinite/no-solution classification from that lab's Unit 3 reappears here in geometric form (intersecting lines / same line / parallel lines) rather than being taught as a brand-new idea from scratch.
**Audience framing:** Built for a student seeing this content for the first time, regardless of the standard's posted grade level. The core new idea — that a system's solution is the ONE point that makes BOTH equations true at once — should be grounded in a graph the student can see two lines crossing on, with that crossing point substituted back into both original equations to verify it, before any algebraic (substitution/elimination) method is introduced as a faster way to find that same point without graphing.

## Units

### Unit 1: What a System's Solution Means — Graphing Two Lines
- **Goal:** Graph two linear equations on the same coordinate plane and discover that their crossing point is the one (x, y) pair that makes BOTH equations true.
- **Standard:** 8.EE.8a
- **Buckets:**
  - Graphing two lines with different slopes that clearly cross at one lattice point, then substituting that point's coordinates into BOTH original equations to confirm it satisfies each one — the foundational verification habit this unit builds
  - Given a candidate point and a system, checking whether that point is a solution by substitution ALONE (no graphing), including a candidate that satisfies only ONE of the two equations — explicitly testing that "satisfies one equation" is not the same as "is the solution to the system"
  - Reading an already-graphed system (two lines already drawn) and identifying the intersection point's coordinates directly from the graph, then verifying algebraically
  - A system where the two given equations, once graphed, turn out to be the SAME line (infinitely overlapping) or two PARALLEL lines (never crossing) — introduced here visually/conceptually (per 8.EE.8a's own "correspond to points of intersection" framing extending naturally to "what if there's no single intersection point, or every point is one") before Unit 3 formalizes the algebraic recognition of these cases
- **Requires intro (CFU gate):** Yes — "the solution to a system is a point that satisfies BOTH equations simultaneously" is the unit's foundational new idea, and the documented misconception it must defend against is treating a point that satisfies only one of the two equations as sufficient; CFU should include a question presenting a point and a system where the point satisfies exactly one equation, asking the student to identify which equation(s) it fails and why it's therefore not a system solution.
- **Memorization fact (periodic re-check candidate):** No — this is a definitional/conceptual understanding, re-verified each time by substitution rather than recalled as a fact.

### Unit 2: Solving Systems Algebraically — Substitution and Elimination
- **Goal:** Find a system's exact solution algebraically, without needing to graph, using substitution or elimination.
- **Standard:** 8.EE.8b (algebraic solving)
- **Buckets:**
  - A system where one equation is already solved for a variable (or easily rearranged), making substitution the natural first method to teach (e.g. y = 2x + 1 paired with 3x + y = 11)
  - A system in standard form (Ax + By = C style, neither equation pre-solved for a variable) where elimination (adding or subtracting the equations, possibly after scaling one by a constant) is the more efficient method — kept distinct from the substitution bucket so students build judgment about WHICH method fits which form, not just execute one memorized method regardless of setup
  - A system requiring the student to scale one or both equations by a constant before terms eliminate cleanly (e.g. coefficients that aren't already opposites or matching), the hardest-tier case in this unit since it adds a setup step beyond directly adding/subtracting
  - A system whose algebraic solving process reveals it has infinitely many solutions (both equations reduce to the same line) or no solution (reduces to a false statement like 0 = 6) partway through substitution/elimination — connecting this unit's method directly back to Unit 1's graphing-based introduction of those same two cases, now reached algebraically instead of visually
- **Requires intro (CFU gate):** Yes — choosing between substitution and elimination based on the equations' given form is a real judgment call with no single "always correct" choice, and a common misconception is applying one memorized method regardless of fit, or mishandling the scale-before-eliminate step; CFU should include a question presenting two systems in different forms and asking which method is more efficient for each, with a one-sentence justification, not just the final numeric solution.
- **Memorization fact (periodic re-check candidate):** No — method selection and execution are case-by-case reasoning, re-derived from the given equations' form each time, not a fixed fact to recall.

### Unit 3: Solving Simple Systems by Inspection
- **Goal:** Look at certain systems and find the solution immediately, without setting up full substitution or elimination, because the equations' structure makes it obvious.
- **Standard:** 8.EE.8b (solve simple cases by inspection)
- **Buckets:**
  - A system where one variable's value is handed directly by one equation (e.g. x = 5 paired with x + y = 9) so the other variable follows in one step without any elimination setup
  - A system where the two equations are obviously inconsistent by inspection alone — same left side, different right side (e.g. x + y = 4 and x + y = 9) — recognized as having NO solution without doing any algebra, purely by comparing the two equations' structure
  - A system where the two equations are visibly IDENTICAL after a trivial rearrangement (e.g. one is literally double the other, like x + y = 3 and 2x + 2y = 6) — recognized as having infinitely many solutions by inspection, distinguished from the no-solution bucket by the fact that the right sides scale consistently with the left sides rather than conflicting
  - A "looks like it needs full algebra but doesn't" discrimination case mixed in among genuinely-needs-elimination systems (carried over as distractors from Unit 2's harder bucket), so mastering this unit means correctly identifying WHEN inspection applies, not applying it indiscriminately to every system handed over
- **Requires intro (CFU gate):** Yes — "solve by inspection" is a judgment skill (recognizing WHEN a shortcut applies) layered on top of Unit 2's full methods, and the standard explicitly names this as its own expectation distinct from general algebraic solving; CFU should include a question asking the student to identify, across several systems, which ones can be solved by inspection and which genuinely need substitution/elimination, with a reason for each — a discrimination task, not a solve-it-yourself task.
- **Memorization fact (periodic re-check candidate):** No — recognizing an inspection-eligible system is pattern recognition re-applied fresh to each system's given structure, not a recalled fact.

### Unit 4: Real-World Problems Leading to Systems
- **Goal:** Read a real-world situation involving two related unknown quantities, set up a system of two equations to represent it, and solve for both unknowns.
- **Standard:** 8.EE.8c
- **Buckets:**
  - A straightforward "two items, two totals" setup (e.g. ticket prices for adults and children, given two different combinations and their total costs) translated into a system and solved
  - A rate/mixture-style context (e.g. two vehicles' combined travel, or combining two quantities at different rates to reach a target) requiring the student to define both variables clearly before writing either equation — emphasizing the translation step, not just the solving step
  - A problem giving the information in a form that doesn't immediately suggest "set up two equations" (e.g. a paragraph describing a relationship and a total, rather than pre-separated clues), requiring the student to first identify what the two unknowns even ARE before writing anything
  - A problem whose resulting system, once set up correctly, has no solution or infinitely many solutions in context (e.g. two pricing plans that are actually identical, or a scenario describing an impossible combination) — testing whether students can recognize and sensibly interpret a degenerate case IN CONTEXT ("these two plans always cost the same" / "there's no way to combine these to get that total"), not just symbolically
- **Requires intro (CFU gate):** Yes — translating a word problem into a correctly defined pair of variables and two matching equations is a distinct skill from solving an already-set-up system (Units 1-3), and the standard explicitly calls out real-world application as its own expectation; CFU should include a question asking the student to define variables and write (but not yet solve) the system for a given scenario, isolating the translation step for direct feedback before computation enters the picture.
- **Memorization fact (periodic re-check candidate):** No — translation and setup are context-dependent reasoning, re-derived fresh for each scenario.
