# MeasurementAndClassifyingLab

**Proposed slot:** MK3 — provisional, confirm at build time per project convention.
**Grade:** K
**Standards covered:** K.MD.1 (describe measurable attributes of objects, such as length or weight; describe several measurable attributes of a single object), K.MD.2 (directly compare two objects with a measurable attribute in common, to see which has "more of"/"less of" the attribute, and describe the difference), K.MD.3 (classify objects into given categories, count the number of objects in each category, sort the categories by count — category counts ≤10).
**Relationship to existing labs:** No existing coverage — first lab for this domain.
**Audience framing:** Built for a student seeing this content for the first time, regardless of the standard's posted grade level. This content is entirely non-numeric/comparative at its core (longer/shorter, heavier/lighter) before any counting is layered on in Unit 3, so Explore should lean on visual/draggable object comparisons (side-by-side bars, a simple balance-scale visual) rather than numbers or rulers — standard units of measurement are explicitly NOT part of this standard and should not be introduced.

## Units

### Unit 1: Describing How Objects Are Measured
- **Goal:** You will be able to name ways an object can be measured, like how long it is or how heavy it is.
- **Standard:** K.MD.1
- **Buckets:**
  - Describe length ("long/short") for a single object
  - Describe weight ("heavy/light") for a single object
  - Describe more than one attribute of the SAME object (e.g. "this book is long AND heavy") — the genuinely harder case where a student must hold two independent descriptions at once instead of picking just one
  - Identify which attribute a given describing word refers to (e.g. "tall" → length, not weight) — a vocabulary-matching bucket distinct from free description
- **Requires intro (CFU gate):** Yes — this is the first unit in the lab and introduces measurable-attribute vocabulary itself; common misconception is conflating size/length with weight (assuming "bigger-looking" always means "heavier"), which the CFU should directly probe.
- **Memorization fact (periodic re-check candidate):** No — naming attributes is a vocabulary-application skill tied to whatever object is shown, not a fixed fact set to memorize.

### Unit 2: Comparing Two Objects Directly
- **Goal:** You will be able to look at two objects side by side and tell which one has more of an attribute, like which is longer or which is heavier, and say how you know.
- **Standard:** K.MD.2
- **Buckets:**
  - Compare length directly (two objects shown side by side, aligned at one end) — the visually easiest case
  - Compare length directly when objects are NOT aligned at a common starting point (e.g. one is shifted) — the genuinely harder case where a student must mentally align endpoints rather than just reading which extends further
  - Compare weight directly (using a simple balance-scale visual showing which side tips down)
  - Describe the DIFFERENCE, not just which is more (e.g. "the red one is longer" vs. "the red one is longer than the blue one by about two blocks") — the standard explicitly calls for describing the difference, not only identifying the winner
  - Near-tie comparisons (two objects very close in length/weight) vs. obviously-different comparisons — near-ties are the harder bucket since the visual difference is subtle
- **Requires intro (CFU gate):** Yes — the "must share a common starting point/alignment to compare fairly" idea is a real misconception point (a student may judge length by which object's far end looks further right on screen, ignoring where each one starts), worth a direct check.
- **Memorization fact (periodic re-check candidate):** No — this is a direct-comparison reasoning skill applied fresh to whatever two objects are shown; nothing here is a fact to memorize.

### Unit 3: Classifying and Counting by Category
- **Goal:** You will be able to sort a group of objects into categories, count how many are in each category, and tell which category has more or fewer.
- **Standard:** K.MD.3
- **Buckets:**
  - Sort objects into categories based on an OBVIOUS, named attribute (e.g. "sort by color," given 2 category labels)
  - Sort objects into categories based on a LESS obvious attribute, or with 3+ categories at once (e.g. sort mixed shapes by type, not just color) — more categories and subtler attributes are the genuinely harder case
  - Count the objects within each already-sorted category (counts ≤10 each) — a distinct step from the sorting itself
  - Order/compare the categories by their counts (which category has the most, the fewest, or compare two specific categories) — the final synthesis step that requires combining sorting AND counting results
- **Requires intro (CFU gate):** Yes — this unit combines two prior skills (classifying + counting, the latter gated in the Counting and Cardinality lab) into a new compound task; common misconception is sorting by the wrong/inconsistent attribute partway through (e.g. starting to sort by color, then switching to sorting by size without noticing), which the CFU should surface.
- **Memorization fact (periodic re-check candidate):** No — classifying and comparing category counts is a reasoning skill applied to whatever objects/categories are presented, not a fixed fact.

## Open questions / flags for the builder
- K.MD.3's "sort the categories by count" step assumes counting fluency up to 10, which overlaps with CountingAndCardinalityLab (MK1) content; flagging that Unit 3 of this lab may want to be sequenced/gated AFTER MK1 is reasonably underway, though per project convention this plan does not hard-require a cross-lab prerequisite lock.
- This standard set has no "how much" numeric measurement (no inches/units) at Kindergarten — only direct, non-numeric comparison. Flagging explicitly so the builder doesn't introduce ruler/unit-based measurement prematurely (that belongs to Grade 1/2 MD standards, not here).
- Unit 1 and Unit 2 both touch "length" and "weight" vocabulary; the builder should keep Unit 1 strictly about describing a SINGLE object's attributes and Unit 2 strictly about comparing TWO objects, to avoid bucket overlap between the two units.
