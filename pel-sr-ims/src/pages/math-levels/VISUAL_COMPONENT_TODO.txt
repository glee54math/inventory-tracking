VISUAL COMPONENT COVERAGE — TODO
=================================
Tracks which math levels have an authored visual practice component (per
MATH_TSX_STYLE_GUIDE.txt conventions) and which still need one. Word
problems don't need this list — the generation pipeline is level-agnostic
and works for any level already (see Student Portal plan, Phase 3/4).

Status legend: [x] authored AND wired into LEVEL_SKILLS (live for students)
               [~] authored but NOT wired in yet (invisible to students —
                   this is the state that caused a live "no practice
                   problems" bug for MG6 on 2026-09-02, so don't assume
                   a component existing means it's actually reachable)
               [ ] needs one authored

When a level gets a new component:
  1. Write it per MATH_TSX_STYLE_GUIDE.txt (named export + Demo default export),
     inside that level's own folder: src/pages/math-levels/{levelId}/{fileName}.tsx.
  2. Add an entry to LEVEL_SKILLS in src/utils/levelSubsections.ts (type,
     skillId, componentFile, componentExport, generateParams) — do this
     immediately, don't leave it for later. A component isn't "done" until
     this step happens; that's the step that actually makes it show up in
     a student's Practice Problems card.
  3. Check this file's box and note the component name below.

[x] MM1  — RatioLab                    (MM1/MM1_RatioLab.tsx) — wired 2026-10-04
          as a "standalone" skill. First package large enough to use the real-
          subfolder exception to section 11's flat-prefix rule: diagrams/, engine/,
          lib/, units/ (27 files total) sit as genuine subfolders directly under
          MM1/, keeping their original short names and cross-imports exactly as
          authored. MM1_RatioLab.tsx is the only other file directly in MM1/
          alongside the empty MM1.tsx shell, which is why it's still the only one
          the admin file browser lists (its glob only goes one level deep).
          Styled with its own CSS file (MM1_RatioLab_styles.css), not Tailwind —
          the original artifact's :root/body/button/h1-h3/p/img rules were fully
          unscoped and would have repainted the entire site; every selector was
          rewritten under a .ratio-lab wrapper class before import. Loads Lexend
          from Google Fonts at runtime, same external-CDN flag as MG11_PowersOfTen.
          2026-10-05: added lib/palette.ts's itemColors (red/green/yellow) + an
          optional color prop on QA/QB/QC (engine/controls.tsx) + colorA/colorB on
          RatioLanguage.tsx's scene data, so a scene whose item names reference a
          real color (e.g. "red apples", "yellow marbles") renders in that color
          instead of defaulting to whichever of qa/qb happens to be assigned to
          it. Only 2 of the 9 scenes across groupScenes/groupWordScenes needed an
          override; everything else still uses the qa/qb/qc default.
          2026-10-05: added an End-of-Unit Test to the "Ratio language" unit only
          (units/RatioLanguageTest.tsx — 7 curated generator functions, each
          randomizing its own numbers, totaling 10 fixed questions; 2 with a
          diagram, 3 with colored QA/QB/QC prompt text, 9/10 passScore). New
          supporting pieces: TestQuestion type (engine/types.ts), RatioStep.tones
          now also accepts "none" for a plain answer box with no qa/qb/qc tint,
          Unit.test? field (units/types.ts), engine/UnitTest.tsx's UnitTestView
          (one question at a time, no hints/reveal/feedback until all 10 are in,
          reuses StepInput/check/answerText exported from StepProblem.tsx),
          useProgress's testScore/recordTest (keeps the best-ever score, not the
          latest), and a "Test" tab + pass/fail badge in MM1_RatioLab.tsx — shown
          only for units with a `test` defined, so the other 5 MM1 units are
          unaffected until each gets its own RatioLanguageTest.tsx-style file.
          Not yet done: the other 5 units' tests, and the eventual student-login
          + Firestore-backed persistence (useProgress's localStorage is explicitly
          the piece designed to swap out for that later).
          2026-10-06: same pass applied to the "Unit rate" unit. Color fix: mixScenes'
          "white paint" → "yellow paint" + colorA/colorB (itemColors only covers
          red/green/yellow, so renamed rather than adding a new entry). New engine
          capability: NumberStep.money? (engine/types.ts) — when set, check() requires
          the typed answer to match exactly two decimal places ("4.50", not "4.5" or
          "2 1/2"), with a dedicated message when the value is right but the format
          isn't; answerText() and StepInput's placeholder updated to match. Applied to
          priceProblem()'s existing unit-price step too, for consistency between
          practice and test. New units/UnitRateTest.tsx (originally 8 generators/10
          questions in the same 2-diagram/3-colored/3-4-3-difficulty shape as
          RatioLanguageTest.tsx; later revised per user feedback to 9 generators/10
          questions — cut the too-easy "just restate the ratio" train question,
          added a 4th multiple-choice question, landing on 1 colored/4 final MC —
          see below). Every money generator picks the unit price first from a
          quarter-dollar pool (exact in binary floating point) and multiplies by an
          integer quantity for any total, so the student's division always
          terminates to the cent, never forcing a round. DoubleNumberLine/TapeDiagram
          print their own axis labels directly on the SVG, so unlike RatioGroups in
          the Ratio Language test, no extra legend was needed for the diagram
          questions here. Later fixes from manual testing: NumberStep.money's
          two-decimal rule only applies when the answer isn't a whole dollar amount
          (so "$4" and "$4.00" are both accepted) — this meant two multiple-choice
          questions' "unformatted price" distractors had to be redesigned (a whole-
          dollar distractor would otherwise have secretly also been correct); multiple
          choice "sentence" questions were also found to not need a format gotcha at
          all (that's what the free-type money questions are for) and were simplified
          to pure arithmetic-mistake distractors; engine/UnitTest.tsx gained a
          "← Previous question" button so a test isn't strictly forward-only.
          2026-10-06: same pass applied to the "Tables & graphs" unit. Color fix:
          tableScenes' "white paint" → "yellow paint" + colorB (same itemColors
          rename pattern as the other two units — "blue paint" already matched QA's
          default blue, so no colorA override was needed). New units/TablesGraphsTest.tsx
          (9 generators/10 questions, 2-diagram/2-colored/3-4-3-difficulty shape) reuses
          RatioTable and CoordinatePlane (both self-label like DoubleNumberLine/
          TapeDiagram, so again no extra legend needed) and lib/math.ts's lcm(), the
          same function compareProblem() already uses for its own "which ratio is
          stronger" practice problem — the final MC question mirrors that same
          common-multiple method. No engine changes needed (this unit doesn't involve
          money).
